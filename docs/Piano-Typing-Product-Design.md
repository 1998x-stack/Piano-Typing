# PIANO TYPING

**Product Strategy, Experience Design & MVP Specification**  
Version 1.0  |  2026-11-17  |  Product proposal  
*Turn every keystroke into a note.*

## 执行摘要

产品定位：一款以自由键盘输入为演奏行为的互动音乐体验。用户在专注文本、练习打字或自由创作时，每次有效按键都能触发即时、悦耳且可控的声音反馈；持续输入逐步形成音乐片段，并可回放和保存。

核心价值不是训练反应速度，也不是把用户锁进下落音符或限时点击玩法，而是降低键盘练习的枯燥感，让真实输入成为音乐创作的媒介。

第一阶段优先证明三件事：输入与声音同步足够自然；随机文本也能生成可听的音乐；用户愿意为了声音体验自愿多输入，同时键盘能力没有被牺牲。

## 1. 产品定义与边界

### 目标用户
- 希望改善盲打和输入稳定性的普通电脑用户；喜欢键盘、声音设计或轻量音乐创作的人；需要低压力、可持续输入练习的学生、写作者和开发者。

### 核心 Job-to-be-Done
- 当我需要练习输入或正在写作时，我希望键盘动作能产生悦耳、可控的音乐反馈，让输入过程更有趣，同时不打断我原本的思路。

### 产品不做什么
- 不做反应速度竞赛；不以每分钟击键数作为唯一成功标准；不要求用户跟随固定节拍；不把自由输入强制转化成英语课程；不把连续签到、随机宝箱或损失惩罚作为主要留存机制。

### 产品边界
- Piano Typing 是“输入即演奏”的产品。它可以支持英语、中文、代码或自选文本，但不负责词汇解释、语义测验、间隔复习或英语能力认证。若未来加入语言学习，应作为可选扩展，不得污染自由演奏主体验。

## 2. 市场观察与机会

### 竞品信号
- TapNoise 与 Mechvibes 证明按键声音、可定制音色和桌面级陪伴体验有独立吸引力；Switch Lab 将键盘声音与打字小游戏结合；Ratatype 代表结构化盲打训练；HN 的打字练习讨论反复出现真实文本、错误可见性、音量控制、难度曲线和手部疲劳等诉求。

### 用户反馈归纳
- HN 用户偏好有意义的文本和真实输入节奏，不喜欢无意义空格、强制不自然动作或屏幕位置与实体键位不一致；声音体验必须允许静音或调整；键盘训练要避免过度施压和不必要的手部负担。

### 机会判断
- 现有产品多在“按键音效”“盲打训练”“节奏游戏”之间择一。Piano Typing 的差异化是把即时声音、可控和声、真实文本输入和个人作品回放合并为一个连续体验。市场信号是需求假设，不等同于已验证的付费意愿或留存。

## 3. 产品原则

### 原则一：真实输入优先
- 所有练习都应允许自然的空格、标点、大小写和纠错；不强迫用户为了游戏而制造不自然输入。

### 原则二：音乐是即时反馈，不是惩罚
- 错误字符可以被柔和提示，但不能触发刺耳噪声、扣生命或毁掉整段演奏。

### 原则三：可预测的映射
- 默认键位到音高的映射在一局内稳定，避免每个和弦变化都重新映射键位，损害肌肉记忆。

### 原则四：自由控制
- 用户可随时暂停、静音、调整音量、选择音色、降低视觉动效和结束练习。

### 原则五：成长以能力衡量
- 提供准确率、稳定性、个人速度趋势和练习时长；不以排行榜或 streak 替代能力进步。

## 4. 核心体验与游戏循环

### 主循环
- 选择模式与音色 → 聚焦输入区域 → 输入任意文本 → 每个有效按键触发音符 → 系统将连续输入组织成乐句 → 结束时回放作品 → 查看键盘表现并决定是否继续。

### 推荐模式
- Free Play：自由输入任何文字，音乐反馈最丰富，不显示速度压力。
- Typing Flow：使用短文或用户导入文本练习真实输入，显示准确率和稳定性。
- Key Focus：按用户薄弱键位/字母组合生成短练习，但不把字母随机散落到屏幕各处。
- Text Studio：导入纯文本、Markdown 或粘贴内容，生成可回放的输入音乐。

### 节奏与时长
- 默认不设置倒计时；用户可选择 3、5、10 分钟轻量 session，也可无限时自由演奏。暂停思考不扣分、不丢失作品。

### 结束体验
- 把本局输入事件转化为一段可回放的作品；展示练习时长、输入准确率、WPM 区间、错误最多的键位/组合和个人趋势。作品命名与分享由用户主动选择。

## 5. 音乐引擎设计

### 双映射策略
- Stable Key Map（默认）：物理键位映射到固定音阶音级与音区，保证同一键在同一 preset 中有稳定音高。优先使用五声音阶作为入门默认，降低随机组合产生刺耳和声的概率。
- Harmony-Aware Mode（可选）：键位决定音级类别，伴奏和和弦进行围绕当前调性组织；不要在每个和弦变化时任意改变单键的基础映射。
- Experimental Mode（高级）：允许半音阶、用户自定义映射和更高自由度，明确提示可能出现不协和音。

### 音乐结构
- 按键事件生成短音符；空格或词间停顿形成呼吸；标点和段落结束触发乐句边界；系统在背景中安排和弦、低音和轻量节奏。用户输入的时间间隔影响节奏，但系统应容忍停顿和思考。

### 音色与合成
- MVP 只需 Felt Piano、Soft EP、Ambient Pluck 三种 preset。使用经过授权的采样或合成音色；每个声音应有包络、音量上限、轻量混响和防削波处理。避免在每次按键时创建大量 React 状态更新。

### 调度架构
- 输入事件直接进入独立 Audio Engine；使用 Web Audio API 的 AudioContext 时间线调度；UI 只订阅压缩后的可视化事件。优先复用 AudioNode/voice pool，控制 polyphony，并处理 voice stealing、页面失焦、AudioContext suspend/resume 和设备输出切换。

### 延迟预算
- 工程目标：在明确的参考设备、浏览器和有线输出条件下，测量 keydown 到可听声音的端到端延迟；目标中位数 ≤50ms、P95 ≤80ms。该指标是 MVP 验收目标，不是所有设备保证值。记录 AudioContext.baseLatency，并在真实设备上测量总延迟。

## 6. 输入、键盘训练与显示反馈

### 输入处理
- 仅当练习输入区获得焦点时处理键盘事件；忽略 event.repeat 的重复触发；组合输入期间识别 compositionstart/compositionend，避免破坏中文输入法；正确处理 Backspace、Shift、CapsLock、Enter、标点和不同键盘布局。

### 布局与键位
- 使用 KeyboardEvent.code 识别物理键位，使用输入框实际文本识别字符；支持 QWERTY 为默认布局，并为 AZERTY、QWERTZ、Dvorak、Colemak 等布局预留配置。不要假设所有键盘都使用相同字符位置。

### 显示层级
- 中央：当前文本/输入光标；下方：可折叠的虚拟键盘；背景：克制的波形/音符可视化；侧边：可选的统计与音色控制。输入时隐藏非必要指标，避免视觉干扰。

### 反馈规则
- 正确字符：音符与键位轻微发光；错误字符：清晰标注但不惩罚；Backspace：回退反馈；连续输入：波形延展；乐句完成：和弦收束。所有反馈可关闭或调低。

### 人体工学
- 默认 session 建议短时段；提供休息提示但不强迫；不鼓励无休止刷分；避免高频闪烁、强震动或要求不自然手指动作。键盘热区仅能估算常见键位，不得宣称通过浏览器准确检测真实手指。

## 7. 得分、成长与指标

### 不使用单一总分
- 产品同时展示输入准确率、速度趋势、稳定性、练习时间和作品完成度。音乐审美不应由算法给用户打“好听分”。

### 建议指标
- Accuracy = 正确字符数 / 已处理字符数；WPM = 正确字符数 / 5 / 有效分钟数（需定义空格、纠错与暂停口径）；Consistency = 有效输入间隔的稳健离散度；Error Recovery = 错误后正确修复的比例。

### 奖励规则
- 允许用户为自己设定目标，例如“连续 3 分钟保持 97% 准确率”或“练习一段自选文章”。完成后解锁可选 preset、视觉主题或作品模板；不扣除既有成果，不用 streak 断裂惩罚。

### 北极星指标
- 建议采用“每周主动练习分钟数 + 输入准确率/稳定性改善”组合观察，而不是单纯 session 时长。D7 回访用于产品健康度，不能代替键盘能力测量。

## 8. MVP 需求与验收

### P0 范围
- 浏览器端单页应用；聚焦输入区；三种音色；稳定五声音阶映射；基础和弦/低音伴奏；实时波形；Free Play 与 Typing Flow；静音/音量/暂停；本地 session 记录；作品回放。

### P0 验收
- 连续输入 10 分钟无崩溃、音频泄漏或失控多音；快速连续按键不出现明显爆音；Backspace、IME、Shift、标点和焦点切换测试通过；用户可随时静音和暂停；作品回放与本局事件顺序一致；默认不上传原始输入文本。

### 性能与可靠性
- 在目标桌面浏览器上记录输入到声音延迟、CPU、内存和掉帧；处理 AudioContext 自动挂起；页面隐藏时暂停或降级；避免重复注册全局事件监听器；确保浏览器快捷键不会被无差别拦截。

### 非功能要求
- Local-first；可选导出作品；键盘导航可用；支持 reduced motion；高对比度与色盲友好状态；明确音量与静音；不请求麦克风权限。

## 9. 路线图与实验

### Phase 0 — 音乐可行性
- 验证 26 个字母、空格和常见标点的映射是否听感连贯；比较固定映射与和声约束映射；邀请 8–12 名用户进行自由输入体验访谈。

### Phase 1 — 可用 MVP
- 完成输入、音频、基本和弦、三种音色、虚拟键盘、作品回放和本地统计；支持粘贴文本。

### Phase 2 — 训练增强
- 加入弱键位/双字母组合统计、个人基线、键盘布局配置、短文库和练习计划。

### Phase 3 — 创作工作室
- 作品收藏、preset 编辑、导出 MIDI/事件文件、可分享的作品页面、用户自定义映射。

### 关键实验
- A/B：固定键位映射 vs. 和声约束映射；简单伴奏 vs. 更丰富伴奏；自由文本 vs. 目标文本；始终显示虚拟键盘 vs. 熟练后逐步隐藏。衡量愉悦度、主动回访、输入准确率和疲劳感。

### 停止/调整条件
- 如果用户认为声音干扰输入，优先降低伴奏密度；如果音乐映射让用户刻意乱敲而不是输入真实文本，分离 Free Play 与 Typing Flow；如果长 session 导致疲劳，缩短默认建议并增加休息提示。

## 10. 风险、隐私与开放问题

### 主要风险
- 映射听感不佳；声音延迟；音色授权不清；IME 和布局兼容差；视觉动画分散注意；用户为作品而乱敲，反而降低真实输入练习质量。

### 隐私基线
- 默认本地处理键盘输入；不记录用户在其他应用中的按键；不收集练习区以外的键盘事件；原始文本只有在用户明确保存/导出时才持久化；分析事件不携带原文、密码样式内容或个人文档内容。

### 待验证决策
- Web 优先还是桌面壳；是否支持 MIDI 键盘；是否加入代码文本 preset；是否提供离线音色包；作品导出格式；用户自定义音阶的高级程度。

## 附录 A. 关键产品指标定义

### 体验指标
- Key-to-sound latency：keydown 到音频输出的端到端延迟；AudioContext.baseLatency 仅是其中一部分。
- Session completion：用户主动结束并生成回放的 session 占比。
- Voluntary return：无通知/强制任务情况下的回访。

### 能力指标
- Typing accuracy、WPM、inter-key interval variability、错误键位分布、常见 bigram latency。所有指标必须公开计算口径并允许用户选择不保存。
